# DCSE RAG-to-HTML Public Proof

Status: public-safe proof-of-flow  
Date: 2026-07-08  
Primary lane: SC  
Operating layer: DCSE database anchor, RAG, pgvector, Command Post activity trail

## Purpose

This folder records a controlled proof that approved Sonly Consulting website direction can move from source material into retrieval-shaped knowledge, then into a generated HTML build artifact.

The goal is to show that DCSE is not only planning a database-backed operating model. It can register approved source material, classify it, embed it, retrieve it under scope, and use that retrieved context to support a website build.

## What was tested

MVT-004 created the RAG-to-HTML build artifact from approved, lane-classified source chunks.

MVT-005 expanded the database policy in a controlled way so approved, non-PS, non-secret, non-quarantined SC sources could be embedded while retrieval remained off.

MVT-006 enabled scoped retrieval for one approved SC source and confirmed the pgvector path could return approved build context.

## What this proves

1. Approved SC source material can be classified by lane, status, safety posture, and intended use.
2. The database can act as the operating anchor for website-build artifacts.
3. pgvector can store chunk-level build context.
4. Scoped retrieval can return approved build context.
5. The generated HTML can be used as a reviewable public-safe build artifact.
6. CP activity can record the policy outcome and preserve operational memory.

## Controlled retrieval posture

The retrieval test was intentionally scoped. The source had to satisfy the safety chain before retrieval was enabled:

```text
approved_for_embedding = true
public_safe = true
ps_lock = false
technical_secret = false
quarantine_required = false
lane = SC
sensitivity = Public or Internal
status = ACTIVE
```

That means retrieval was opened for an approved source, not for the whole database.
