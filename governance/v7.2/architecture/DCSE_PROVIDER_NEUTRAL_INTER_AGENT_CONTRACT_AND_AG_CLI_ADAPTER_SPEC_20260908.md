# DCSE Provider-Neutral Inter-Agent Contract and AG/Gemini CLI Adapter Specification

Status: CANDIDATE
Authority: DCS
Lane: DCSE / Command Post
Task ID: DCSE-ORCH-20260908-002
Classification: INTERNAL

## 1. Purpose

Define the provider-neutral contract by which the DCSE Universal Dispatch Controller coordinates governed AI workers and deterministic validators, with an initial adapter target for Google Gemini CLI / Anti-Gravity execution surfaces.

This specification extends the operative v7.2 control-plane direction. It does not create a second poller. It assumes one neutral dispatch controller with provider adapters beneath it.

## 2. Design Principle

The orchestrator owns workflow state. Workers own bounded execution. The Rules Engine owns deterministic policy and validation. DCS owns final authority at material gates.

Workers exchange structured tasks, artifacts, evidence, and receipts rather than relying on conversational continuity.

## 3. Canonical Lifecycle

TASK -> CLAIM -> EXECUTE -> ARTIFACT -> RECEIPT -> VALIDATE -> CONTINUE / RETRY / ESCALATE -> CLOSE

Every transition must be externally observable and independently verifiable.

## 4. Provider-Neutral Worker Contract

Each adapter must implement the following logical operations:

1. identity()
   - Return worker identity, runtime, model family, version, host, and capabilities.

2. preflight(task)
   - Validate runtime availability, tool access, working directory, lane authorization, required inputs, output paths, and explicit stop conditions.

3. claim(task)
   - Accept a bounded task already authorized by the controller.

4. execute(task)
   - Run the provider CLI or agent runtime with the approved instruction packet and bounded permissions.

5. heartbeat(state)
   - Emit liveness, active task, phase, elapsed time, retry count, and relevant metrics.

6. collect_artifacts()
   - Enumerate generated files, code, reports, manifests, patches, tests, media, or other deliverables.

7. submit_result()
   - Return structured result metadata and completion evidence.

8. release(reason)
   - Release the claim as success, retryable failure, blocked, or policy stop.

9. resume(session_ref)
   - Resume an interrupted provider session only when the controller authorizes continuation.

## 7. Artifact Contract

Every material output must be treated as a first-class artifact.

Each artifact record should contain:

- artifact_id
- task_id
- type
- path_or_uri
- content_hash
- version
- created_by
- created_at
- source_inputs[]
- validation_status
- promotion_status
- reusable = true / false
- registry_target

Scripts generated by workers are not disposable. A successful script should be assessed for registration as a reusable executable enterprise asset.

## 8. Rules Engine Integration

The Rules Engine is a standalone deterministic module invoked by the orchestrator at defined gates.

Minimum gate points:

1. task admission
2. worker eligibility
3. lane/firewall validation
4. secret exposure validation
5. artifact validation
6. state transition validation
7. release/publication validation
8. promotion validation

AI workers may propose candidate rule interpretations, but deterministic rule evaluation controls progression.

## 9. AG / Gemini CLI Adapter Scope

Initial adapter name:

DCSE_AG_GEMINI_CLI_ADAPTER

Purpose:
Provide a bounded adapter that allows the Universal Dispatch Controller to assign governed tasks to the local Google Gemini CLI / Anti-Gravity execution surface and collect structured outputs.

The adapter must not assume that Anti-Gravity and Gemini CLI are synonymous. Runtime discovery must identify the actual executable, version, wrapper, and invocation path present on the host.

## 10. AG / Gemini CLI Runtime Discovery

Before implementation, perform read-only discovery of:

- installed Gemini CLI executable(s)
- version(s)
- invocation syntax
- available noninteractive/headless flags
- working-directory behavior
- session/resume support
- JSON or structured output modes
- model selection controls
- tool permission controls
- filesystem write controls
- environment-variable dependencies
- authentication mode without exposing credentials
- timeout behavior
- exit codes
- artifact locations
- log locations
- compatibility with Windows, PowerShell, WSL, and any AG wrapper

Output must classify each finding VERIFIED, LIKELY, or UNKNOWN.

## 11. Adapter Execution Pattern

Controller
-> authorized task packet
-> AG/Gemini adapter preflight
-> deterministic admission checks
-> CLI invocation
-> heartbeat/progress
-> output capture
-> artifact enumeration
-> test execution
-> deterministic rule validation
-> result submission
-> receipt
-> continue / retry / escalate

## 12. CLI Safety Requirements

The adapter must:

- avoid placing secrets in prompts, logs, stdout, receipts, or artifacts
- use approved environment or credential broker mechanisms
- enforce working-directory boundaries
- deny PS/PPR access unless specifically authorized
- deny publication and destructive actions by default
- capture exact command metadata without credential values
- enforce bounded timeout and retry limits
- preserve stdout/stderr for evidence when safe
- never convert a planning-only task into a write task without authority

## 13. Reusable Asset Promotion

A worker-produced script may become an enterprise asset only after:

1. source capture
2. static review
3. dependency inventory
4. deterministic test execution
5. security review
6. rollback/recovery assessment
7. documentation
8. content hash generation
9. registry entry
10. promotion approval under current governance

## 15. Gap Analysis

VERIFIED:
- DCSE already has task claim, heartbeat, result, and receipt concepts in the current repository.
- The operative architecture requires a provider-neutral Universal Dispatch Controller.
- The current repository contains provider-specific worker implementations and Supabase worker RPC lineage.

LIKELY:
- Gemini CLI is installed or used elsewhere in the DCS environment, based on DCS direction, but this must be runtime-verified before implementation.
- Anti-Gravity may be a wrapper or execution surface around Gemini capabilities rather than the canonical executable name.

UNKNOWN:
- Exact local executable path, version, headless flags, JSON output support, session-resume behavior, and credential mechanism for the current AG/Gemini runtime.
- Whether the current host already contains an AG-specific wrapper script outside GitHub.

## 17. Exit Criteria

The candidate is not operationally complete until:

1. actual Gemini CLI / AG runtime is runtime-verified
2. one governed task is claimed and executed through the adapter
3. heartbeats are recorded
4. artifacts are collected and hashed
5. deterministic rules are evaluated
6. result and receipt are persisted
7. failure and retry behavior are tested
8. unauthorized lane/PS access is denied
9. secrets remain outside model context
10. the Supabase discovery certification run completes with zero writes
11. reusable discovery code is registered as an enterprise asset
12. DCS receives only material exception/approval gates
