## 3. Modified or rejected findings

| Copilot proposal | Reconciliation | Reason |
|---|---|---|
| Add a DCS authority token or signature field to DCL | Rejected | Authority references and promotion receipts are required; secret-like authority tokens do not belong in model-visible DCL payloads. |
| Use a numeric computed promotion score | Rejected | Promotion is authority-based, not score-based. |
| Make registry tags replace the fixed always-on set | Modified | Master Profile, D03, D21, and D22 remain the constitutional bootstrap. Registry tags may confirm but cannot silently replace it. |
| Require automatic webhooks, polling, or cache invalidation | Modified | Distribution mechanisms are adapter-specific and require evidence under D22. |
| Require one fixed preview evidence package for every UI | Modified | Preview adapters select evidence appropriate to the artifact and environment. |
| Treat every hash mismatch or capability gap as `BLOCKED_RESERVED` | Rejected | Affected work is isolated as `DRIFT` or `BLOCKED_CAPABILITY`; reserved status applies only when a reserved condition also exists. |
| Treat reviewer outcome as promotion approval | Rejected | Review validates and recommends. It does not create promotion authority. |
