## Verified source findings

- D15 models only a simplified remote database, local JSON inbox, and offline evidence store.
- A file inbox is described as a database without the transaction, locking, durability, and authorization controls required of a database.
- Remote access is constrained to one client pattern rather than an explicit access-mode and exposure model.
- RLS guidance does not distinguish authentication, grants, row authorization, policy composition, or service-role bypass.
- No physical schema adapter, environment registry, object access matrix, or data classification contract exists.
- Migrations, schema drift, production hotfix capture, rollback, forward recovery, idempotency, preview parity, and generated types are not governed completely.
- The embedded backup script uses `shell=True`, places the database URI in a shell command, and hardcodes a Windows path.
- The source lacks complete Auth, Storage, Realtime, Queues, Cron, Edge Function, view, trigger, function, and RPC controls.
- Missing D15 triggers global halt instead of isolating affected database actions.

## DCSE historical evidence reviewed

The following verified history directly shaped the correction:

- PR #9 recorded 43 Supabase security-advisor findings before remediation and three residual findings afterward.
- Provider API keys were stored in browser localStorage and transmitted in request bodies before server-side correction was defined.
- PR #15 and its RLS certification found eleven material database defects plus a migration-order defect, including caller-asserted worker identity, missing claim foreign keys, no lease enforcement, no duplicate-result constraint, cross-worker mutation, incomplete expired-claim recovery, mutable `search_path`, and unintended RPC execution rights.
- The first authorization matrix produced only 8 valid passes out of 15. Several earlier claimed passes were false because unrelated errors caused denial before the intended authorization control executed.
- Direct production hotfixes were not captured in migrations, and nonconforming migration version names caused local and remote history mismatch.
- A preview branch lacked dependent `dcse_cp` state, so a green provider deployment did not prove the complete result bridge.
- CR-SEC-001 documented an obsolete no-JWT endpoint that accepted caller-asserted identity and minted a worker token without an enrollment secret. It was replaced with a deterministic HTTP 410 tombstone while the authenticated broker remained.
- Supabase task history recorded repeated RLS remediation, a non-atomic claim-assignment defect, and completion claims that required later evidence reconciliation.

## Official platform changes incorporated

- Data API grants and RLS are separate security layers.
- Supabase is moving new and existing projects toward explicit opt-in grants for newly created Data API objects, with an enforcement milestone announced for October 30, 2026.
- OpenAPI schema enumeration using an anonymous key was removed for existing projects in April 2026.
- GraphQL introspection defaults changed for new pg_graphql versions in 2026.
- Explicit extension version pinning is being deprecated on hosted Supabase beginning August 5, 2026.
- Modern publishable and revocable secret keys are preferred over legacy long-lived keys.
- Database backups do not include Supabase Storage objects.
