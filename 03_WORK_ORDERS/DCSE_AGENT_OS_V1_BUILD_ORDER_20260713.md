# DCSE Agent OS v1 Build Order

Date: 2026-07-13
Status: ACTIVE BUILD
Authority: DCS
Branch: build/dcse-agent-os-v1
Lane: DCSE / Command Post / DDNA

## Executive Direction

Build DCSE Agent OS v1 as the operating environment for multiple AI agents, local and open-source models, interactive chat, custom workflows, persistent memory, DDNA, product development, media production, approvals, deployment preparation, and evidence capture.

Pilot 1, Baller4Life / SJL Driving Exceptional Student App, and Pilot 2, Bee Beauty, join the active priority portfolio. They do not replace CTJ, TSL, websites, RAG, media, DDNA, Command Post operations, employment products, or other approved work.

## Portfolio Priority Model

### Foundation Priorities

1. Command Post Agent OS shell
2. Interactive in-dashboard chat and conversation history
3. Agent and model registry
4. Workflow execution engine
5. Approval and decision gates
6. Artifact, media, and durable URL registry
7. RAG and source locator
8. Relay listener, heartbeats, task events, and observability

### Active Product Priorities

1. CTJ
2. TSL
3. SC and SS websites and web applications
4. Baller4Life / SJL Driving Exceptional Student App
5. Bee Beauty
6. DCS Employment products and resume traffic web presence
7. Media, voice, image, and video production workflows
8. Tribunal Manager and governed intake

No active product priority is displaced merely because another product becomes a pilot.

## Required Interactive Chat

The Agent OS must support interactive conversation from within the dashboard. Chat must be more than a visual mockup.

Required chat capabilities:

- Start and resume conversations
- Select an agent, model, project, entity, and lane
- Attach approved files and source references
- Invoke workflows from chat
- Stream status updates and partial results
- Preserve conversation turns
- Link messages to tasks, artifacts, approvals, and receipts
- Route outputs to DDNA review and RAG eligibility checks
- Enforce lane isolation and model authorization
- Support frontier, local, and open-source models through adapters

## Initial Build Sequence

1. Establish the Agent OS branch and working shell.
2. Build the interactive dashboard layout and local conversation behavior.
3. Represent the full portfolio without displacing existing priorities.
4. Add workflow launcher cards for source intake, product build, website build, media build, RAG intake, and daily command.
5. Add model registry representation for frontier, coding, local, and raw divergence agents.
6. Add approval states, artifact status, and recent activity.
7. Bind dashboard chat and portfolio data to Supabase operational tables.
8. Add provider-neutral model adapters.
9. Add local model discovery and health checks.
10. Implement the Baller4Life / SJL workflow as the first deep product pilot.
11. Implement Bee Beauty as the second deep product pilot.
12. Continue CTJ, TSL, websites, RAG, media, and other active product work through the same operating system.

## Immediate Deliverable

The first increment is a working static Agent OS shell containing:

- Mission Control
- Active portfolio
- Workflow launcher
- Interactive chat panel
- Agent and model dock
- Approval queue
- Artifact and media status
- System activity feed

The static shell is a functional front-end increment. It must be followed by Supabase persistence, authenticated execution, model routing, workflow state, and deployment integration.

## Governance Controls

- DDNA Governance Hub remains the constitutional authority.
- SC SportsSociety remains the operational application and orchestration repository unless superseded by approved architecture.
- Pilot products do not receive automatic public release authority.
- Local raw divergence models may reason broadly but may not publish, deploy, delete, expose credentials, modify production data, or cross protected lane boundaries.
- Parallel agents must work in isolated branches, worktrees, workspaces, or artifact namespaces.
- Public deployment, paid services, DNS changes, destructive operations, and protected-lane access require DCS approval.

## Definition of Done for Increment 1

Increment 1 is complete when:

1. The Agent OS shell loads as a standalone web page.
2. The portfolio includes CTJ, TSL, websites, RAG, Baller4Life / SJL, Bee Beauty, media, DDNA, and Command Post operations.
3. Chat accepts messages and preserves the local session conversation.
4. Workflow cards can be launched and produce visible run-state activity.
5. Model and agent selections affect the chat session header.
6. Approval, artifact, and activity panels update visibly.
7. The branch contains a clear path for Supabase and model-adapter integration.
