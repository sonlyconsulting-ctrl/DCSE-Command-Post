## Decision

DCS explicitly wants discussion and planning before implementation.

The architecture interview is therefore a discovery and reconciliation artifact, not a build authorization.

Current interview artifact:

`SC_DIGITAL_ESTATE_ARCHITECTURE_INTERVIEW_20260813.md`

## Purpose of the interview

Collect business objectives, site/product roles, Wix boundaries, visual direction, hosting inventory, Vercel/Netlify state, Substack/public profiles, Chat/F&A capability, product/membership/service formulas, data ownership, GitHub/Supabase/Tribunal control, AI execution routing, cost/subscription constraints, analytics/search, privacy/security, and implementation sequence.

Unknown answers become verification tasks. They are not filled with guesses.

## Required decision artifacts after interview

### A. Digital Estate Inventory
Every known public, hosting, publishing, data, identity, AI, and operational surface.

### B. Asset Disposition Matrix
`CURRENT ASSET -> PURPOSE -> VALUE -> DEFECT/RISK -> KEEP/REWORK/MERGE/REPLACE/ARCHIVE/QUARANTINE -> OWNER`

### C. Experience Architecture Matrix
`EXPERIENCE -> RENDERER -> DATA OWNER -> BUSINESS SERVICE -> AUTH MODEL -> HOST -> SOURCE CONTROL -> EVIDENCE PATH`

### D. Design Contract
Shared visual and interaction rules.

### E. Offer Architecture
Product, membership, service, booking, bundle, and program formulas.

### F. Publishing/Profile Architecture
Canonical source, Wix Blog, Substack, Google/Bing, SEO/AEO/GEO, approval, and measurement.

### G. AI/Tool Execution Matrix
`TASK TYPE -> PRIMARY TOOL -> BACKUP -> COST CLASS -> DATA CLASS -> AUTHORITY -> RECEIPT`

### H. Deployment/Portability Plan
Wix, Vercel, Netlify, GitHub, CLI, Supabase, rollback, and portability.

### I. Tribunal/GitHub/Supabase Crosswalk
Stable work identity and evidence path.

### J. DCS Implementation Decision Packet
Recommended target architecture, alternatives, cost, risks, migration sequence, rollback, and approval gates.

## Validation rule

Implementation should not begin simply because a plan looks good.

Required validation: source facts reconciled, risks visible, unknowns bounded, lane firewall intact, data ownership decided, renderer decided, rollback defined, cost implications visible, acceptance criteria stated, and DCS decision recorded.
